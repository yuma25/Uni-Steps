# Uni-Steps

AIと仲間が支える課題管理プラットフォームである．

## 📁 プロジェクト構造とファイル内容

各ディレクトリの役割と，現在作成済みの主要ファイルの内容である．

### 1. `domain/` (ドメインレイヤー)
ビジネスロジックの核となるデータ構造とインターフェースである．
*   `user.go`: ユーザー情報の構造体定義である．
*   `group.go`: グループ情報の構造体定義である．
*   `task.go`: 課題・予定情報の構造体定義である．クリティカルフラグ（起床確認）を含む．
*   `repository.go`: データベース操作の抽象的なインターフェース定義である．

### 2. `usecase/` (ユースケースレイヤー)
アプリの具体的な「動き」を組み立てる場所である（準備中）．

### 3. `interfaces/` (インターフェースレイヤー)
外部（HTTPリクエスト等）との窓口である．
*   `handler/task_handler.go`: Echoフレームワークを使用したHTTPハンドラーである．標準パッケージとの違いをコメントで解説している．

### 4. `infrastructure/` (インフラレイヤー)
データベースや外部API（Gemini, LINE）との具体的な通信処理である．

### 5. `docs/` (ドキュメント)
*   `overview.md`: アプリのコンセプトと機能概要である．
*   `architecture/design.md`: クリーンアーキテクチャと処理フローの図解である．
*   `infrastructure/architecture.md`: インフラ構成と無料運用の仕組みである．
*   `references/packages.md`: 使用ライブラリの公式リファレンス集である．
*   `references/commands.md`: 開発用コマンド（Format, Lint, Build）のまとめである．

---

## 🛠 エンジニアの開発工程

実際のプロの現場で行われる開発のステップである．詳細は `docs/engineering_workflow.md` を参照すること．

1.  **Research (調査)**: 課題の理解と技術的な実現可能性の確認である．
2.  **Strategy (戦略)**: アーキテクチャ設計とデータ構造の決定である．
3.  **Execution (実行)**:
    *   **Plan**: 1つの機能（例：タスク登録）ごとの具体的な実装計画である．
    *   **Act**: コードの実装である．
    *   **Validate**: テストと動作確認である．
4.  **Review & Improve**: コードの品質チェックと改善である．
