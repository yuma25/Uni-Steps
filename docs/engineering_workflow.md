# プロのエンジニアリング・ワークフロー

このプロジェクトを通じて学べる，プロの現場での開発手順を解説する．

## 1. 開発の 3 大サイクル

エンジニアは闇雲にコードを書くのではなく，以下のサイクルを回すのである．

### ① Research (調査)
「何を作るか」と「どう作るか」を徹底的に調べるのである．
*   ユーザーが本当に困っていることは何か．
*   使用するライブラリ（Echo, Gemini）で何ができるか．
*   pkg.go.dev などの公式ドキュメントを読み込み，仕様を理解する．

### ② Strategy (戦略)
全体像を設計するのである．
*   データベースのテーブル設計を行う．
*   クリーンアーキテクチャに基づいたフォルダ構成の決定を行う．
*   今回の `docs/architecture/` にあるような図解を作成する．

### ③ Execution (実行: Plan -> Act -> Validate)
ここが実際のコーディングである．さらに 3 つに分かれる．
1.  **Plan (計画)**: これから書くコードの「入出力」と「手順」を日本語で書き出すのである．
2.  **Act (実装)**: 計画に沿ってコードを書くのである．1つの機能ごとに小さく作る．
3.  **Validate (検証)**: 書いたコードが期待通り動くかテストするのである．

---

## 2. 具体的なコーディングの手順

初心者が迷わないための，1つの機能（例：タスク登録）を作る時の手順である．

### ステップ 1: ドメイン（Domain）を定義する
まず「何というデータが必要か」を `domain/` に書くのである．
*   `task.go` に構造体を作る．
*   `repository.go` に「DBに保存する」というインターフェース（予約）を作る．

### ステップ 2: ユースケース（Usecase）を書く
次に「具体的な動き」を `usecase/` に書くのである．
*   ここでは「DBへの書き方」は気にせず，「もしDBが保存してくれたら，次はAIを呼ぶ」といった**手順のロジック**だけを書くのである．

### ステップ 3: 窓口（Handler）を作る
`interfaces/handler/` にリクエストを受け取る口を作るのである．
*   ユーザーからデータを受け取り，Usecase に渡す役割である．

### ステップ 4: 道具（Infrastructure）を実装する
最後に，本物のデータベースや AI API と通信するコードを `infrastructure/` に書くのである．

---

## 3. なぜこの順番なの？

この順番で作る理由は，**「一番大事なもの（ビジネスロジック）を，周りの道具（DBやAPI）の都合から守るため」**である．
これを意識するだけで，あなたのコードは「プロっぽい，修正に強いコード」になるのである．
