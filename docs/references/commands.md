# 開発コマンドリファレンス

本プロジェクトの開発で使用する主要なコマンドである．品質維持のため，コミット前には必ずこれらのチェックをパスする必要がある．

> [!IMPORTANT]
> バックエンド（Go）に関するコマンドを実行する際は，必ずプロジェクトのルートから `backend` ディレクトリへ移動（`cd backend`）した上で実行してください．

---

## 1. フォーマット (Format)
コードのスタイルを標準的な形式に整えるコマンドである．

```bash
# backend ディレクトリに移動
cd backend

# プロジェクト全体のコードを整形する
go fmt ./...
```

## 2. 静的解析 (Lint)
コードの不備やバグの可能性を検出するコマンドである．本プロジェクトでは `golangci-lint` の使用を推奨する．

```bash
# backend ディレクトリに移動
cd backend

# golangci-lint を実行する（インストール済みの場合）
golangci-lint run
```

## 3. ビルド (Build)
プログラムが正しくコンパイルできるか確認するコマンドである．

```bash
# backend ディレクトリに移動
cd backend

# メインプログラムをビルドする
go build -o main .
```

## 4. 実行 (Run)
サーバーを起動するコマンドである．

```bash
# backend ディレクトリに移動
cd backend

# 開発用（ビルドせずに直接実行）
go run main.go

# 本番用（ビルド済みバイナリを実行）
./main
```

## 5. 依存関係の整理
使用していないパッケージの削除や，必要なパッケージの追加を行うコマンドである．

```bash
# backend ディレクトリに移動
cd backend

# 依存関係を最新の状態に整理する
go mod tidy
```

## 🛠 自動チェックの二段構え

### 1. コミット前の自動チェック (Git Hook)
本プロジェクトでは，`.git/hooks/pre-commit` にチェック用のスクリプトを配置している．これにより，`git commit` 実行時にローカル環境で自動的にチェックが行われる．

### 2. GitHub 上での自動チェック (GitHub Actions)
GitHub へコードを `push` した際，または `Pull Request` を作成した際に，GitHub Actions によってクラウド上でも同様のチェックが実行される．`.github/workflows/ci.yml` に定義されており，これがパスしない限りマージは推奨されない仕組みである．これにより，環境の違いによるビルド失敗や，ローカルでのチェック漏れを確実に防ぐことが可能である．
